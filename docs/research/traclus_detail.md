# TRACLUS (Trajectory Clustering) 알고리즘 상세 가이드

TRACLUS는 "Partition-and-Group" 프레임워크를 기반으로 하며, 긴 궤적을 의미 있는 선분(Segment)으로 나누어 부분적인 유사성을 찾는 데 특화되어 있습니다.

## 1. 알고리즘 원리 (3단계)

### 단계 1: Trajectory Partitioning (궤적 분할)

- **목적**: 하나의 궤적을 여러 개의 직선 선분으로 나눕니다.
- **방법**: MDL(Minimum Description Length) 원리를 사용하여, 궤적의 특징이 급격히 변하는 지점(Characteristic Points)을 찾습니다.
- **축구 데이터 적용**: 공이 패스되거나, 드리블 방향이 꺾이는 지점을 자동으로 감지하여 분할합니다.

### 단계 2: Segment Grouping (선분 군집화)

- **목적**: 분할된 수많은 선분들 중 서로 유사한 것들을 묶습니다.
- **유사도 지표**: 세 가지 거리의 가중치 합을 사용합니다.
    1. **Perpendicular Distance**: 두 선분 사이의 수직 거리 (위치 유사성)
    2. **Parallel Distance**: 두 선분 사이의 평행 거리 (매칭 구간 유사성)
    3. **Angle Distance**: 두 선분 사이의 각도 차이 (방향 유사성)
- **군집화**: DBSCAN과 유사한 밀도 기반 알고리즘을 사용하여 군집을 형성합니다.

### 단계 3: Representative Trajectory Extraction (대표 궤적 추출)

- **목적**: 각 클러스터를 대표하는 하나의 전형적인 이동 경로를 생성합니다.
- **방법**: 군집 내 선분들의 평균적인 위치와 방향을 계산하여 하나의 "전술적 경로"로 시각화합니다.

## 2. 데이터 요구사항 및 전처리

### 필요한 데이터 형식

- `sequence_id`: 각 공격 시퀀스를 식별하는 ID
- `x, y`: 공의 좌표 (Normalization 완료된 0~1 값 권장)
- `order/timestamp`: 시퀀스 내의 순서 정보

### 핵심 전처리

1. **Smoothing (평활화)**: GPS 오차나 데이터 노이즈를 제거하기 위해 Kalman Filter나 Moving Average 등을 적용합니다.
2. **Normalization (정규화)**: 경기장 규격에 따른 차이를 없애기 위해 0~1 또는 0~100 사이로 좌표를 변환하고, 공격 방향을 단일 방향(예: 왼쪽에서 오른쪽)으로 통일합니다.
3. **Resampling (재샘플링)**: 너무 촘촘하거나 듬성듬성한 데이터 포인트를 일정한 간격(예: 0.1초 단위)으로 조정합니다.

## 3. 전술적 분석 예시: "Lateral to Box" 패턴

- **상황**: 윙어가 사이드 라인을 따라 직선으로 드리블하다가 박스 안으로 컷인(Cut-in) 패스를 찌르는 시퀀스.
- **TRACLUS 작동**:
  - **분할**: '사이드 라인 직선 구간'과 '중앙으로 꺾이는 패스 구간'으로 나뉩니다.
  - **군집화**: 다른 시퀀스들의 '사이드 라인 드리블' 선분들은 이 클러스터의 앞부분에 묶이고, '박스 침투 패스' 선분들은 뒷부분에 묶입니다.
  - **결과**: 시퀀스 전체 길이가 다르더라도 "사이드 돌파 후 컷인"이라는 핵심 선분 조합을 가진 모든 시퀀스를 동일한 전술 군집으로 찾아냅니다.
