## Research Question

> 슈팅과 박스 진입에 앞선 공격 전개에서 반복되는 공간 패턴을 찾고, 그 과정의 어떤 행동이 득점 기회를 높이거나 실점 위험을 낮췄는지 설명할 수 있는가?

- **분석 단위** — 슈팅 수나 득점 수는 공격의 결과만 요약할 뿐 기회를 만들기까지 거친 경로는 보여주지 않아, 패스와 운반을 연결한 전개 과정 자체를 분석 단위로 삼음.
- **패턴의 정의** — 성과로 이어진 이벤트 좌표열이 반복되는 형태를 가리키며, 감독의 의도나 선수 전체의 움직임까지 담은 전술 라벨은 아님.

## Method

### Design Principles

- **성과에서 거꾸로 분석 단위를 잡음** — 임의의 시간 구간 대신 슈팅이나 상대 박스 내 행동에서 출발해 이전 전개를 역추적함.
- **시퀀스를 비교 가능한 형태로 먼저 맞춤** — 같은 공격도 진영, 기록 방식, 이벤트 경계에 따라 다른 좌표열로 남아, 표현 학습 전에 방향, 연속성, 중복, 종료 조건부터 정의함.
- **좌표 복원으로 전개를 학습함** — 전술 유형을 사람이 미리 붙이지 않고, 좌표열을 복원하는 과정에서 행동 사이의 공간 관계가 임베딩에 담기도록 함.
- **패턴은 팀 단위로 찾음** — 팀마다 스타일이 달라 시퀀스를 팀별로 분리해 내부 반복성을 보고, 군집 수는 미리 정하지 않고 밀도가 낮은 사례는 노이즈로 남김.
- **패턴과 행동 가치를 분리함** — 자주 나오는 전개가 가치까지 높은 것은 아니어서, 임베딩은 패턴의 유사성만, VAEP는 행동의 기여만 설명하도록 따로 계산한 뒤 해석 단계에서 합침.

### 1. Event Cleaning and Continuity

원본 이벤트에는 경기, 피리어드, 시간, 팀/선수, 행동 유형과 결과, 시작/종료 좌표가 있지만 이벤트 사이의 위치는 연속적으로 기록되지 않음. 이를 이어 붙일 수 있는 형태로 정리하는 작업이 첫 단계임.

- **좌표 정규화** — 105 × 68m 경기장 기준으로 범위를 보정하고 좌표를 0–1로 정규화함.
- **리시브 보정** — 후속 행동과 위치가 겹치는 리시브는 중복 기록이라 제거하고, 실제로 이동이 있었던 리시브는 운반 행동으로 바꾸거나 인접한 운반 행동에 합침.
- **단절 검사** — 정제 후 이전 행동의 종료점과 다음 행동의 시작점 사이 간극을 검사해, 허용 오차를 넘는 단절을 역추적 경계로 씀. 이 경계가 없으면 서로 이어지지 않은 장면이 하나의 공격으로 묶임.

### 2. Outcome-Anchored Sequence Extraction

성과 후보는 슈팅이거나 상대 박스 영역에서 시작하는 유효 행동이며, 태클, 인터셉트, 클리어링, 골키퍼 수비 같은 수비 행동은 후보에서 뺌.

- **박스 판정** — 왼쪽에서 오른쪽으로 공격할 때 x > 0.84, 0.36 < y < 0.635로 정의함. 이 y 범위는 슈팅 판정에도 그대로 쓰여, 실제 박스 전체나 모든 슈팅을 포괄하지 않고 분석 편의를 위해 좁힌 정의임.
- **역추적 중단 조건** — 경기/피리어드가 바뀌거나, 이미 다른 시퀀스에 쓰인 행동을 다시 만나거나, 공격팀 좌표가 끊기거나, 세트피스를 만나면 멈춤. 상대팀의 개입 자체는 시퀀스에 포함함.
- **추출 조건** — 목표 공격팀 행동 수 8개, 성과가 아닌 행동 중 순수 패스 최소 3개, 전체 이벤트 최소 5개로 고정함. 경계에서 일찍 끊기거나 상대팀 행동이 섞여 실제 길이는 조건과 다를 수 있음.
- **혼전 제외** — 성과 이전의 비성과 행동이 이미 박스 안에서 시작하는 시퀀스는 혼전으로 보고 제외해, 박스 도달 이전의 전개만 남김.
- **공격 방향 통일** — 시퀀스를 구성한 뒤 경기, 피리어드, 팀별 골키퍼 평균 위치로 공격 방향을 추정하고, 시퀀스 안 양 팀 이벤트에 같은 좌표 변환을 적용해 상대적 위치 관계를 유지함.

### 3. Spatial Representation Learning

입력은 성과에서 과거로 정렬한 행동 시작 좌표열뿐이며, 팀/선수 이름, VAEP, 시간 정보, 행동 유형은 넣지 않고 공간 경로만 표현하게 함.

- **모델 선택** — self-attention으로 행동 사이의 관계를 함께 볼 수 있는 Transformer 구조를 택함. [Vaswani et al., 2017](https://proceedings.neurips.cc/paper/2017/hash/3f5ee243547dee91fbd053c1c4a845aa-Abstract.html)의 번역 모델과 목적은 다르지만, 시퀀스를 표현하는 원리는 좌표 재구성에도 그대로 적용됨.
- **학습 목표** — 위치 정보를 더한 좌표열을 인코딩한 뒤 입력 좌표를 복원하도록 학습시키고, 재구성 MSE를 최소화해 전개의 공간 정보가 보존되도록 유도함.
- **임베딩 요약** — 짧은 좌표열은 패딩하고 긴 것은 잘라 길이 8에 맞춘 뒤, 유효한 위치의 인코더 표현을 평균 내 하나의 임베딩으로 요약함.
- **데이터 증강** — 학습 중 경기장 폭 방향을 반전해 좌우 대칭 전개도 함께 학습함.

### 4. Team-wise Pattern Discovery

임베딩을 팀별로 나눠 각 팀 안에서만 비슷한 전개를 찾음. 팀 간 군집 번호가 같다고 같은 패턴을 뜻하지는 않아, 군집은 팀 내부 비교에만 씀.

- **OPTICS 선택** — 군집 수를 미리 정하기 어렵고 공격 빈도도 팀마다 고르지 않아, 밀도 구조를 순서로 드러내고 그 구조에서 군집을 뽑는 밀도 기반 방법을 택함 ([Ankerst et al., 1999](https://sigmodrecord.org/publications/sigmodRecord/9906/OPTICS_%20ordering%20points%20to%20identify%20the%20clustering%20structure.pdf)).
- **거리와 노이즈** — 임베딩 간 Euclidean 거리를 쓰고, 밀도가 충분히 형성되지 않은 시퀀스는 억지로 묶지 않고 노이즈로 남김.
- **해석 범위** — 군집은 반복되는 공간 형태를 보여줄 뿐이며, 전술적 의미는 개별 시퀀스와 행동 가치를 같이 보고 판단함.

### 5. Action Valuation with VAEP

패스, 운반, 슈팅 같은 행동의 가치를 성공 여부가 아니라 행동 직전과 직후의 득점/실점 가능성 변화로 평가함. 이 접근이 VAEP임 ([Decroos et al., 2019](https://doi.org/10.1145/3292500.3330758)).

- **상태 표현** — 행동을 SPADL 형식으로 표준화하고, 현재 행동을 포함한 최근 3개 행동의 유형, 결과, 시간, 위치, 이동, 팀 관계로 경기 상태를 표현함.
- **확률 모델** — CatBoost 분류기 두 개로 가까운 미래의 득점과 실점 여부를 각각 예측함. 기본 예측 구간은 다음 10개 행동이며 탐색된 설정에 따라 조정됨.
- **가치 계산** — 평가 대상 팀 관점에서 득점 확률 증가량과 실점 확률 감소량을 더함. 소유권이 바뀌는 상황에서도 같은 팀 관점으로 맞춰 비교함.

$$
V(a_i)=\bigl[P_{score}(S_i,t)-P_{score}(S_{i-1},t)\bigr]
      +\bigl[P_{concede}(S_{i-1},t)-P_{concede}(S_i,t)\bigr]
$$

- aᵢ는 평가할 행동, Sᵢ는 행동 이후 상태, t는 평가 대상 팀이며, 값이 양수면 공격/수비 측면에서 모델이 추정한 순가치가 개선됐다는 뜻임.
- **계산 예시** — 득점 확률이 0.02에서 0.05로 오르고 실점 확률이 0.01에서 0.008로 내려갔다면 이 행동의 가치는 0.032가 됨. 계산 방식을 보여주는 예시일 뿐 실제 경기에서 나온 값은 아님.
- **해석 범위** — 비슷한 경로의 공격에서 어느 행동이 기회를 더 키웠는지 비교하는 데 씀. VAEP가 높다고 감독의 의도였다거나 실제 득점의 원인이었다고 단정할 근거는 아님.

## Experiments and Results

### Experimental Setup

| 구분 | 설정 | 평가 목적 |
| --- | --- | --- |
| 분석 단위 | 목표 공격팀 행동 8개, 비성과 패스 최소 3개, 전체 이벤트 최소 5개 | 비교할 공격 전개의 조건 고정 |
| 표현 학습 | Transformer Autoencoder, 길이 8, 폭 방향 반전 증강 | 좌표열의 공간 정보 재구성 |
| 모델 탐색 | TPE 50회, 탐색당 15 epochs | 재구성 MSE 최소화 |
| 탐색 범위 | 임베딩 차원 32–512, 층 1–8, attention head 2–16, dropout 0.1–0.3 | 표현 용량과 정규화 조정 |
| 최적화 설정 | 학습률 0.0001–0.01, 배치 크기 16, 32, 64 | 학습 조건 탐색 |
| 최종 학습 | 시퀀스 순서 기준 90:10 분할, 최대 100 epochs, 10회 연속 미개선 시 조기 종료 | 재학습 중 오차 모니터링 |
| 군집화 | 팀별 OPTICS, 기본 최소 이웃 수 3, 밀도 변화 기준 0.01 | 반복 패턴과 저밀도 사례 분리 |
| 가치 평가 | CatBoost 득점/실점 모델, 행동 단위 무작위 5-fold, Brier score | 확률 예측 오차 평가 |

- **재구성 MSE** — 패딩 부분의 오차를 0으로 만든 뒤 계산하며, 평균의 분모에 패딩 위치도 들어가 유효 길이에 따라 값이 달라질 수 있음.
- **Brier score** — 예측 확률과 실제 발생 여부의 제곱 오차 평균이라 낮을수록 좋음.
- **지표 간 관계** — 좌표 재구성, 득점/실점 확률 예측, 군집의 전술적 해석은 서로 다른 평가 대상이라, 한 지표가 좋아졌다고 전체 분석이 우수하다고 보기는 어려움.

| 대시보드 | 12개 팀의 공격 시퀀스 205개 | 개별 전개와 행동 가치 탐색 |

- **파이프라인 연결** — 이벤트 정제, 성과 중심 추출, 공간 표현 학습, 팀별 군집화와 행동 가치 시각화를 하나의 흐름으로 연결하는 것까지 확인함.
- **해석 범위** — 재구성 오차가 줄었다고 해서 전술 발견이 정확해졌다거나 경기 성과가 좋아진다는 뜻은 아님.

## Problems and Solutions

- **좌표 반전으로 공격 궤적이 끊김**
  - 원인 — 반전의 단위를 개별 팀 이벤트로 잡아, 공격팀과 상대팀 이벤트가 각자의 공격 방향 기준으로 따로 반전됨. 같은 장면 안에 서로 다른 좌표계가 섞여 공이 경기장 반대편으로 튀는 것처럼 보임.
  - 해결 — 반전 단위를 공격 시퀀스로 바꾸고, 공격팀 방향을 기준으로 상대팀 이벤트까지 같은 변환을 적용함. 공격/수비 행동 사이의 상대적 위치가 유지되어 방향 차이가 별도 패턴으로 학습되는 것을 막음.

- **리시브 중복과 이동 누락이 전개를 왜곡**
  - 원인 — 후속 패스와 위치가 겹치는 리시브가 같은 지점을 중복 기록하고, 리시브와 다음 행동 사이의 실제 이동은 누락돼 경로에 빈 구간이 생김.
  - 해결 — 중복 리시브는 삭제하고, 이동이 담긴 리시브는 운반 행동으로 바꾸거나 인접한 운반 행동에 병합함. 보정한 운반 구간은 관측 정보를 바탕으로 한 추정이라는 한계가 남음.

- **하나의 공격이 여러 패턴으로 중복 집계**
  - 원인 — 박스 진입 후 슈팅과 후속 행동이 연달아 이어지면 각 성과 후보에서 역추적한 구간이 서로 겹치고, 박스 주변 혼전까지 별도 공격으로 잡힘.
  - 해결 — 고정된 대기 간격 대신, 이미 쓰인 행동을 만나면 역추적을 멈추고 박스 안에서 시작하는 시퀀스는 제외함. 중복 집계는 줄었지만 박스 안에서 시작하는 의미 있는 공격도 함께 걸러지는 선택 편향이 남음.

- **연결되지 않은 장면이 하나의 공격으로 묶임**
  - 원인 — 시간상 이웃한 이벤트라도 공간적으로 이어진다는 보장이 없어, 그대로 묶으면 모델이 비현실적인 장거리 이동을 하나의 전개로 학습함.
  - 해결 — 리시브와 이동을 먼저 보정한 뒤 좌표 단절을 판별하도록 순서를 정하고, 공격팀 쪽 단절 지점에서 역추적을 끊음. 보정으로 메울 수 있는 간극과 분석 경계로 삼을 단절을 이 순서로 구분함.

- **군집 점수와 분석 목적이 어긋남**
  - 원인 — 시퀀스 길이, 최소 패스 수 같은 추출 조건과 군집 점수를 한꺼번에 최적화해, 표현이 좋아진 것인지 분석 대상이 쉬워진 것인지 구분되지 않음.
  - 해결 — 추출 조건(길이 8, 최소 패스 3)은 고정하고 표현 학습 목표를 좌표 재구성 오차 최소화로 한정했으며, 군집화는 학습된 표현을 해석하는 단계로 분리함. 재구성 오차가 낮다는 것만으로 전술적 쓸모가 증명되지는 않아, 패턴 안정성과 전문가 해석은 별도 검증이 필요함.

- **분석 결과와 영상이 연결되지 않음**
  - 원인 — 결과 저장 위치와 파일명 규칙이 흔들려 군집/시퀀스와 영상의 대응이 끊기고, 인코딩 환경 차이로 시각화 결과물이 만들어지지 않는 경우도 있었음.
  - 해결 — 팀, 군집, 시퀀스 대응 관계를 기준으로 영상 명명과 탐색 방식을 통일하고, 인코딩 실패 시 쓸 대체 경로를 마련함. 재생성할 때마다 데이터와 영상의 일치 여부는 계속 확인이 필요함.

## Limitations

- **독립 검증이 부족함** — TPE 탐색은 학습/평가에 같은 시퀀스를 쓰고 증강 여부만 다르며, VAEP도 경기 단위가 아닌 행동 단위로 나눠 인접한 상태가 학습과 평가에 함께 들어갈 수 있음. 학습에 쓰이지 않은 경기에서 일반화되는지는 확인하지 못함.
- **분석 대상이 편향돼 있음** — 슈팅/지정 박스 조건과 최소 패스 수를 만족한 공격만 뽑아, 실패한 공격이나 짧은 역습, 박스 내부 전개 전체를 대표하지 않음.
- **관측 정보가 제한적임** — 이벤트 좌표만으로는 오프더볼 움직임, 수비 대형과 압박, 실제 이동 경로, 전술적 의도를 복원할 수 없음. 골키퍼 위치가 부족한 장면에서는 공격 방향 추정도 흔들림.
- **표현 방식이 위치 중심임** — 같은 경로를 다른 속도나 다른 행동 구성으로 수행한 공격을 구분하기 어렵고, 평균 임베딩과 길이 제한이 순서 정보를 얼마나 보존하는지도 검증되지 않음.
- **재현 과정의 연결 지점이 많음** — 행동 식별자 정합, 정제된 공격과 가치 평가의 매칭, 팀별 군집과 화면 데이터의 연결, 최종 시퀀스와 통계의 동기화를 다시 확인해야 함. 탐색 실패 처리와 최적 모델 상태 보존도 보완이 필요함.

### Future Work

- **경기 단위 분리** — 학습, 검증, 테스트를 경기 단위로 나누고 여러 난수 초기값으로 반복해, 재구성 오차와 확률 예측의 변동을 확인할 필요가 있음.
- **비교 기준** — 원시 좌표, DTW 기반 경로 비교, GRU를 같은 데이터 분할로 비교해 Transformer 표현 학습의 실제 기여를 검증할 필요가 있음. 시간/행동 유형을 추가했을 때 구분력이 나아지는지도 봐야 함.
- **전처리 ablation** — 방향 통일, 리시브 보정, 중복 제한, 단절 경계를 하나씩 빼보며 각 결정이 시퀀스 품질과 군집 안정성에 기여하는 정도를 확인할 필요가 있음.
- **전문가 평가** — 전문가가 해석한 패턴과의 일치도, 사례 탐색의 효율성, 군집 밀도와 행동 가치가 각각 주는 정보를 평가할 필요가 있음.
- **확률 보정** — 득점/실점이 원래 드물다는 점을 감안한 기준 모델과 비교해, 예측 확률이 실제 발생률과 얼마나 맞는지 확인할 필요가 있음.

## How to Run

- **Python 환경** — `python -m venv .venv`, `.venv\Scripts\Activate.ps1`, `pip install -r requirements.txt` 순서로 설치함. lockfile이 없어 버전까지 같은 재현은 보장되지 않음.
- **웹 대시보드** — `web/`에서 `npm ci`, `npm run build`, `npm run dev` 순서로 실행함. Vite 7 요구에 맞는 Node.js가 필요함.
- **입력 데이터** — 원시 이벤트 CSV와 경기 정보 CSV를 `data/`에 두어야 함. 원본 데이터는 저장소에 포함하지 않음.
- **실행 순서** — 스크립트는 아래 순서로 의존하며, 통합 실행기는 `scripts/run_v5_9_final_pipeline.py`임.

```text
scripts/preprocessing.py
→ scripts/convert_to_spadl.py, scripts/compute_vaep.py
→ scripts/sequence_extraction.py, scripts/train_embedding_model.py, scripts/extract_embeddings.py
→ scripts/team_based_clustering.py, scripts/team_animations.py
→ scripts/prepare_web_data.py
```

- **상세 문서** — 재현 범위와 알려진 제약은 [docs/reproduction.md](docs/reproduction.md)에 정리함.
